What the Syntax Tree Gives Up

The target module is read and parsed from its syntax tree only. It is never imported or executed, so its top level code does not run during generation. A test set is written for each function the module itself defines at top level. The default count is ten tests per function. The values supplied are bounded random strings and integers, together with floats, booleans and None where the annotation asks for them. Where an annotation is absent the value defaults to a string. Where an annotation names a kind the generator does not know, including list and dict, the value likewise falls back to a string, which is a genuine fuzz case and also, plainly, not the type the author wrote.

Placeholder Usage Line

The printed usage line from the README reads ./codeintel-fuzz-test-generator [params]. It is reproduced exactly and flagged as a placeholder that names neither the positional path nor any of the measures it pretends to summarise.

The Positional Path the README Forgot

The run begins with the positional module path, in the form python3 main.py MODULE_PATH. Without that path no run begins, yet the README parameter list never names it. The fuller account of types, varargs and keyword only arguments is held here beside the README version, so both versions stand in the record.

python3 main.py MODULE_PATH --num_tests 10 --string_length 10 --int_min -100 --int_max 100

When the Module Will Not Parse

The random source is never seeded, so two runs over the same module produce different tests, and a failing case must be saved from its own run because rerunning will not reproduce it. The generated tests catch their own exceptions and merely print them, so the exit code of a generated file stays at nought even when a case has failed, and only a reader of the printout learns of the failure. A module which cannot be read or parsed ends the run at exit 1 and writes no output file. A readable module defining no functions of its own likewise ends the run at exit 1. The argument checks refuse a missing path, a test count of nought or below, a string length of nought or below, and an integer minimum above its maximum, each with exit 1.
